6TH GRADE · FINAL BUILD SPRINT

Complete. Test. Debug. Document.

Mission / Misión: Complete and refine your interactive project, prove that its computational logic works, test the full user experience, fix bugs and leave clear documentation so another person can understand and use it.

🎮 Teacher Warm-up · Code Battle Live ↩ Review Cycle 4 Project Lab

🎯 Learning Objective · Objetivo de aprendizaje

EN: Refine and complete an interactive digital project by applying variables, conditionals, loops and arrays/lists/data collections; then test, debug and document the solution so it can be understood and used by others.

⚡ 2-Hour Didactic Sequence

0–12 min

1. Opening & Motivation · Activación

Lasallian greeting. Ask: “How can we make our projects better?”

Run a short 6th Grade Code Battle Live as a retrieval warm-up on variables, conditions, loops and debugging.

12–25 min

2. Completion Check · Diagnóstico rápido

Each team audits its own project using the checklist below. They identify Done / Needs improvement / Missing.

25–82 min

3. Final Build Sprint · Construcción y refinamiento

Teams complete missing functionality, improve interaction and show the teacher the computational concepts in their own code/project.

Variable→Decision→Loop→Collection→User interaction
82–103 min

4. Test & Debug Sprint · Pruebas y depuración

Students test complete user flows, record expected vs. actual behavior, identify bugs and apply fixes. A peer should test the project without receiving step-by-step help from the creators.

103–114 min

5. Documentation Sprint · Documentación

Add project title, purpose, team first names, instructions, controls, relevant comments and a short explanation of the computational logic.

114–120 min

6. Closure · Action & Expression

Quick progress check: “What have you completed? What’s left?” Reflection: “What was the most difficult part of building your project?” Lasallian prayer.

🚀 Final Build Mission

By the end of Cycle 5, your team should be able to demonstrate the project—not only show the screen. Every member should understand what the project does and where the main computational concepts appear.

✅ Project Completion Checklist

1 · Computational Logic

  • At least one meaningful variable
  • A condition / decision
  • A loop / repeated process
  • An array, list or data collection
  • User input or interaction

2 · Functionality

  • Main experience works from start to finish
  • Controls/buttons work
  • No known critical bug
  • Feedback is visible to the user
  • The objective is understandable

3 · Testing & Debugging

  • Team tested the full project
  • Peer tested the project
  • Expected vs. actual result recorded
  • At least one bug/fix documented
  • Final retest completed

4 · Documentation

  • Project title
  • Purpose / problem addressed
  • First names of team members
  • How to use / controls
  • Relevant code comments or instructions

5 · Communication

  • Every member can explain the project
  • Team can point to variables/conditions/loops
  • Team can explain one challenge
  • Team can explain one improvement
  • Team can receive critical feedback

6 · Final Evidence

  • Working project file/link
  • Testing evidence
  • Short documentation
  • Reflection completed
  • Ready for teacher review

🧪 Testing Protocol

Developer Test

Expected: What should happen?

Actual: What really happened?

Bug: What failed?

Fix: What did you change?

Retest: Did it work after the change?

Peer Test

Give the project to another student/team. Do not explain every step.

Observe:

  • Can they understand how to start?
  • Are controls/instructions clear?
  • Can they complete the main experience?
  • Where do they get confused?
