9TH GRADE · CYCLE 4 · MVC + JAVASCRIPT

Smart To-Do · Software Architecture Challenge

Mission: build, document and present a functional To-Do List application using MVC architecture to solve a real organization problem in the school or community.

Review MVC Introduction

🎯 What you must build

Your application must use Model–View–Controller and work with three connected entities: User, Task and Category. The technology stack is HTML, CSS and JavaScript. Your solution must connect to a real organizational need and an ODS.

🧭 Complete route

PROBLEM→ODS→USERS→DATA MODEL→MVC DIAGRAM→MODEL→VIEW→CONTROLLER→MVP→TEST→REFACTOR→DOCUMENT→PITCH

⚡ Acceleration rule

Do not restart if you already have useful work. Identify your current level and continue from there. If you are beginning, start with the real problem and data model before writing code.

Project levels

LEVEL 1Problem + ODS + Users + MVC Diagram
LEVEL 2User, Task, Category models + basic UI
LEVEL 3Create / Edit / Complete / Delete / Filter
LEVEL 4Validation + localStorage + search + statistics + responsive UI
LEVEL 5Testing + refactor + documentation + ODS reflection + pitch

MODEL · What does the system know?

USER id name CATEGORY id name color TASK id title description status userId categoryId createdAt

VIEW · What does the user see?

SMART TO-DO [ + NEW TASK ] TASK: Math homework CATEGORY: Academic USER: Emma STATUS: Pending [ EDIT ] [ COMPLETE ] [ DELETE ] FILTER: All / Pending / Done

CONTROLLER · What happens when the user acts?

USER CLICKS "ADD TASK" ↓ CONTROLLER READS FORM ↓ VALIDATES DATA ↓ MODEL CREATES TASK ↓ MODEL DATA CHANGES ↓ VIEW RENDERS AGAIN

Minimum functional requirements

  • Create users
  • Create categories
  • Create tasks
  • Assign task to a user
  • Assign category to a task
  • Edit task
  • Mark complete / pending
  • Delete task
  • Filter tasks
  • Prevent invalid empty records

Professional upgrades

  • localStorage persistence
  • Search
  • Task counters / statistics
  • Responsive design
  • Useful empty states
  • Confirmation for destructive actions
  • Clean MVC file organization
  • Readable comments
