10TH GRADE · CYCLE 4 · STEM PROJECT

Build Something That Matters.

Mission: design, develop, document and present a functional interactive web application that addresses a real problem in your school or community, connecting technology with STEM thinking and the Sustainable Development Goals.

🎯 Learning objective

Apply structured programming, interface design, data manipulation, problem solving and collaborative development to transform a real need into a functional web solution using JavaScript + HTML + CSS.

🧭 Your road map

REAL PROBLEM→ODS→USERS→SOLUTION→PLANNING→UI→CODE→DATA→TEST→DOCUMENT→PITCH

⚡ This week: accelerate

If your team already has work, do not restart. Locate your current milestone and continue. If you are beginning, start at Milestone 1. By the end of the week your team should have moved from an idea or exercise toward a clearly planned and demonstrable STEM application.

🚀 4-session acceleration plan

SESSION 1 · DEFINEReal problem, target user, ODS, project name, solution, team roles and success criteria.
SESSION 2 · DESIGNWireframe, inputs, outputs, data, algorithms, functions, conditions, loops and arrays.
SESSION 3 · BUILDHTML structure, CSS interface, JavaScript logic, DOM interaction and first functional MVP.
SESSION 4 · PROVETesting, debugging, improvements, documentation, ODS reflection and progress pitch.

1 · Problem + ODS

  • What real problem are you solving?
  • Who experiences it?
  • What evidence shows that it matters?
  • Which ODS connects naturally to it?
  • What would success look like?

2 · Define the product

Your solution may be a game, simulator or data-management tool, but it must have a purpose.

USER → INPUT → PROCESS → DATA → DECISION → OUTPUT

3 · Plan before coding

  • Project name
  • Problem statement
  • Target user
  • ODS connection
  • Team roles
  • Wireframe
  • Inputs / outputs
  • Data to store
  • Functions required
  • Success criteria

4 · Programming evidence

Your application should demonstrate purposeful use of:

  • Variables
  • Conditionals
  • Loops
  • Functions
  • Arrays
  • Data manipulation
  • DOM / user interaction
  • Readable comments

5 · Team architecture

Use the roles to accelerate rather than divide the project into isolated pieces.

DEVELOPER → implementation and logic TESTER → test cases, bugs and evidence DOCUMENTER → project log and technical documentation UI DESIGNER → wireframe, usability and interface PRESENTER → project story, ODS impact and pitch EVERY MEMBER → understands the complete solution

6 · Build your MVP

Your first version does not need every feature. It must prove the central idea works.

index.html ↓ Interface structure styles.css ↓ Clear responsive UI JavaScript ↓ Logic + Events + Functions + Arrays + Data ↓ FIRST WORKING MVP

7 · Test like a developer

TEST | INPUT | EXPECTED RESULT | ACTUAL RESULT | PASS/FAIL | FIX 01 | | | | | 02 | | | | | 03 | | | | |

Use browser developer tools, peer review and debugging. A bug found and explained is engineering evidence.

🏁 Evidence your team must build toward

  • Project planning document
  • Team project log / bitácora
  • Complete functional JavaScript with comments
  • HTML/CSS user interface
  • Screenshots or screen recordings
  • Technical documentation
  • ODS impact reflection
  • Oral presentation and pitch
  • Self-assessment and peer assessment
  • Final STEM portfolio

📱 No computer right now? Keep moving.

From a phone or notebook you can complete the problem definition, ODS justification, user profile, wireframe, pseudocode, data model, functions, test plan, project log and role assignment. Arrive at the computer with decisions already made.

✨ Before you say “finished”

  • The application solves the problem you defined.
  • The interface can be understood by the target user.
  • The JavaScript is functional and organized.
  • The required programming structures have a real purpose.
  • Your team tested and improved the product.
  • You can explain the ODS connection without reading a copied definition.
  • Every team member can explain how the application works.
  • You have evidence of the process, not only the final screen.
