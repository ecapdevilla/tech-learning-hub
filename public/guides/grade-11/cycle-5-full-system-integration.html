4 · Integration Requirements

Sensor → Data

Generate or simulate a meaningful sensor value and make its current state visible.

Web → Control

The interface must perform a meaningful action: ON/OFF, value, mode or another justified control.

Actuator

At least one actuator or simulated output must visibly respond to system logic or user control.

Persistence

Store useful historical readings in localStorage and recover them after refresh.

History

Stored data must be used: show readings, status changes, events or another useful history.

Alert

Create at least one justified notification or alert based on a sensor value or system condition.

About “Database” in this cycle: The official activity specifies localStorage for historical data. In this guide, localStorage is the persistence layer for the required practice. A remote database is not required to close Cycle 5.

5 · Historical Data With Purpose

const reading = {
  timestamp: new Date().toISOString(),
  humidity: 32,
  temperature: 29,
  pump: "ON"
};

function saveReading(reading) {
  let history = [];
  try {
    history = JSON.parse(localStorage.getItem("sensorHistory")) || [];
    if (!Array.isArray(history)) history = [];
  } catch {
    history = [];
  }

  history.push(reading);
  history = history.slice(-20); // keep recent history
  localStorage.setItem("sensorHistory", JSON.stringify(history));
}
Do not store data just to satisfy a requirement. Your application must retrieve and use the stored information—for example, to show recent readings, status history or trends.

6 · Alerts Are Engineering Decisions

function evaluateHumidity(humidity) {
  if (humidity < 30) {
    showAlert("Low soil humidity");
    return "critical";
  }
  return "normal";
}

Before accepting a threshold, explain: Why this value? What should happen? Is it a warning or critical condition? Should the actuator respond automatically? Should the event be stored?

11 · Final Definition of Done

System

  • Sensor produces/simulates data
  • ESP32 / Wokwi logic
  • Actuator/output responds
  • Web displays system state

Integration

  • Meaningful web control works
  • History persists in localStorage
  • History returns after refresh
  • Sensor-based alert works

Project Closure

  • Complete flow tested
  • Peer review completed
  • Team can explain data flow
  • Final version is demonstrable
Cycle 5 closure: The goal is a stable, explainable final version at the scope reached by the team—not an endless list of new features. Close critical integration gaps, prove the complete flow and document what remains as future improvement.
