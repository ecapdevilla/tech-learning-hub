FASE 1 Diseño & arquitectura
  • Problema real · identificar necesidad en la escuela/comunidad
  • Arquitectura MVC · bocetos, diagramas (Lucidchart/Draw.io)
  • Definir Modelo (datos), Vista (UI), Controlador (lógica)
  • Estructura de carpetas: /src, /docs, index.html
  • Asignación de roles: Product Owner, Dev, Tester, Documentador, UI
  • Crear repositorio y plan de trabajo
🧠 Prompt sugerido (IA): “Dame un ejemplo de arquitectura MVC para una To‑Do List con Usuario, Tarea y Categoría en JavaScript vanilla.”
FASE 2 Codificación & pruebas
  • Implementar MVC con JavaScript puro (sin frameworks)
  • Modelo: clases Usuario, Tarea, Categoría
  • Vista: renderizado dinámico con DOM
  • Controlador: eventos, actualización de datos y vista
  • Pruebas · depuración · refactorización
  • Persistencia en localStorage o array
  • Documentación del código con comentarios JSDoc
// Ejemplo: Controlador class TareaController { constructor(modelo, vista) { this.modelo = modelo; this.vista = vista; } agregarTarea(datos) { /* lógica */ } }
🤖 Prompt IA: “Refactoriza este código MVC para que sea más modular y fácil de probar.”
FASE 3 UI · ODS · entrega
  • Interfaz final con HTML/CSS (responsive, accesible)
  • Integrar ODS (reflexión y reporte) en la app o documentación
  • Documentación técnica completa: README, manual de usuario, diagramas
  • Preparar presentación oral y pitch (3 min)
  • Autoevaluación y coevaluación (rúbricas)
  • Demostración funcional del sistema
  • Entrega del portafolio STEM: código, capturas, reflexión
🌱 ODS aplicados: ODS 4 (educación de calidad), ODS 12 (producción y consumo responsables)
